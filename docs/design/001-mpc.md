# ADR 001 — MPC 签名协议

> 日期：2026-05-11 | 状态：draft | 作者：qc + DeepSeek

---

## 决策

采用 **GG20 t-of-n 门限签名**，阈值 `t=2, n=3`。客户端持 1 分片，服务端持 2 分片。完整私钥永不拼接，任何单方无法签名。

## 备选

| 方案 | 取舍 |
|------|------|
| GG20 (CGGMP) | 4-6 轮通信，RTT ~200ms。IBM CGGMP 是增强版但轮数相当。成熟度最高 |
| FROST | 2 轮签名但 Schnorr 限定（非 ECDSA）。AA 链上验签走 ECDSA，不兼容 |
| 纯 MPC (SPDZ) | 通用 MPC 太重，Gas 成本不可控 |

## 架构

```
Client                 Axon Service
  │                         │
  ├─ KeyShare A (client)    ├─ KeyShare B (server-1)
  │                         ├─ KeyShare C (server-2)
  │                         │
  ├── Round 1 ──────────────┤
  ├── Round 2 ──────────────┤
  ├── Round 3 ──────────────┤  (GG20 4-6 rounds)
  ├── Round 4 ──────────────┤
  │                         │
  ▼                         ▼
      Signature (ECDSA)
```

## 关键约束

- **密钥生成**：DKG (Distributed Key Generation)，生成时三方在线。客户端分片加密持久在设备本地。
- **签名延迟**：完整 MPC 签名 <200ms。Pre-signing batch 预先生成未绑定 tx 的部分签名，串行化离线。
- **服务端分片**：etcd Learner 持久化，加密存储，启动时解封（KubePivot etcdmanager 同模式）。
- **泄露模型**：单分片泄露 = 零危害。需要 t 个分片同时泄露才可能伪造签名。

## KubePivot 复用思想

| KubePivot | Axon MPC |
|-----------|----------|
| sharding.Lease (分片抢占) | MPC 分片分配 + 续约 |
| state.StateMachine (12 状态) | MpcState 状态机 (Idle→Init→Signing→Done) |
| backpressure token bucket | 并发签名数限制 (每分片) |
